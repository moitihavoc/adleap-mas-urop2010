# Meeting note, 20 Nov 2026: POMCP that reads traces

Full method, math, code map and caveats: `docs/trace_pomcp/trace_pomcp_method.pdf`. Numbers: `results_analysis/LOG.md`
(20 Nov entries). Everything is reproducible with `results_analysis/evaluate_trace_pomcp.py` and
`results_analysis/demo_pomcp_traces.py`.

## 1. The message in one paragraph
Following your feedback, I moved from imitating a teacher (model-free) to planning with POMCP on a world that contains
traces. I checked your claim that POMCP "naturally" uses traces. In the original code it cannot: POMCP plans on a world
where traces are deleted, and its belief drops every teammate it cannot see. Simulating traces alone also cannot change
its decisions, because rewards and teammates ignore traces. Traces can only help by changing **what POMCP believes about
the hidden world**: traces as observations. So I built a planning world that carries traces, plus a belief that reads them
with their true meaning (the "native speaker", our new teacher). **Reading traces makes POMCP's guesses about hidden
teammates far more accurate (1.3 vs 5.6 cells off), but this does not yet make it play better.** The evidence points at
POMCP's model of what teammates *do* as the next bottleneck.

## 2. What I built (no framework files changed; 53/53 tests pass)
- `TracePlanningEnv`: POMCP's imagined world now carries traces, and imagined steps create them with exactly the real
  rules. The "breakpoint" is a test plus a demo: in one decision POMCP imagined 576 steps and 576 traces.
- Three beliefs, changing one thing at a time:
  - **C0**: the framework as is.
  - **C1**: corrected, no traces. Hidden teammates are put back, the task prior is right (U(0.3, 1.5)), and the task count
    is right.
  - **C2**: C1 + reading traces. Rule 1: a hidden teammate is near its youngest trace, ahead along its bearing. Rule 2: a
    hidden task lies along a bearing. Rule 3: a help trace means a task next to it with level = emitter level + deficit.

  C2 vs C1 isolates the effect of traces.

## 3. Results (100 hard scenarios)
**Belief accuracy** (C1 → C2), when the agent senses a trace of a hidden teammate:
- distance to the teammate: **5.6 → 1.3 cells**;
- guesses on its exact cell: **2% → 43%**;
- hidden tasks: 3.2 → 2.9 cells, 8% → 13% exact.

Figure: `results_analysis/Plots/pomcp_trace_belief.png`. At one moment, C2 puts the hidden teammate on its true cell in 99%
of guesses (C1: 1.5%).

**Games** (all tasks done, and C2 − C1 steps, paired by scenario):

| Search per decision | C0 | C1 (no traces) | C2 (traces) | C2 − C1 steps |
|---|---|---|---|---|
| 0.1 s | 89% | 79% | 82% | −1.1 ± 11.2 |
| 0.5 s | 95% | 89% | 92% | +5.0 ± 9.4 |
| 2.0 s | – | 94% | 97% | −1.1 ± 8.7 |

There is **no detectable effect on play** at any budget. It is not only a lack of search: at 2.0 s, C1/C2 search more than
C0 at 0.5 s and still show no trace effect. Both still play worse than C0, which believes the teammates don't exist.

## 4. What I think it means
1. Traces **do carry a learnable "language"**: with the true meaning, the belief improves a lot. So C2 is a sound teacher
   (ceiling) for *belief*.
2. A better belief about *where* teammates are doesn't help if POMCP can't predict *what they do*. In imagination, a
   teammate of unknown type gets a random heuristic (l1–l6), so plans that rely on teammates (joint loads) are mispredicted.
   This is my hypothesis, not yet tested.
3. Honest limits:
   - C1 ignores the agent's own memory of where it last saw teammates, so the belief gain is "traces vs. nothing", not
     "traces vs. memory".
   - One game per scenario.
   - My laptop suspended during some runs. Outcomes are still valid; only the timing averages are inflated, so I report
     medians.
   - Run order slightly favoured C2, and it still showed no effect.

## 5. Next steps (proposed)
1. **Teammate-model test:** rerun C1/C2 with the teammates' true types in imagination. If C2 then beats C1, traces pay off
   once teammates are predicted well.
2. **C3, learning the language:** train a network on logged episodes to predict where hidden teammates and tasks are from
   the sensed traces. Labels are what really happened, with no teacher involved. Plug it into the belief instead of my
   hand-written rules, and report how much of the C1 → C2 gap it closes.
3. **C1 + memory control**, then a harder setting (bigger grid, smaller view) where hidden information matters more.
